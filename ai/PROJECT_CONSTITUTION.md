# Project Constitution & Core Principles

InfraGuard is a defensive IT infrastructure visibility product built for commercial enterprise excellence.

The project must not implement malware, exploitation, offensive security, password cracking, brute force, phishing, or payload generation features. All features must solve real infrastructure visibility, monitoring, inventory, analysis, or reporting problems.

---

## The 10 InfraGuard Product Principles

1. **One Click First**
   - Users should complete most tasks within 3 clicks. Primary actions must be instantly accessible.

2. **Every Screen Must Educate**
   - Zero generic empty states. Every empty view or pending state must serve as an educational onboarding launchpad explaining setup time, prerequisites, and expected outcomes.

3. **Every Metric Must Be Actionable**
   - Never show meaningless standalone numbers. Every metric or status card must explain _why_ it matters and _what action to take next_.

4. **Every Error Must Explain the Solution**
   - Error messages must state not only what went wrong, but provide exact steps or actions to resolve the issue.

5. **Every Feature Must Save Administrator Time**
   - Reduce administrative friction, eliminate repetitive manual workflows, and streamline routine IT ops.

6. **Performance First**
   - Page loads must complete in `< 2 seconds`. Subnet network discovery scans must complete in `< 45 seconds` for a `/24` subnet.

7. **Offline Friendly**
   - Graceful resilience during network interruptions with local caching and offline-friendly indicators.

8. **Accessibility by Default**
   - Full keyboard navigation (`Tab` / `Shift+Tab`), high-contrast colors (WCAG 2.1 AA compliant), and semantic HTML screen reader support.

9. **Commercial UI Consistency**
   - Adhere strictly to the Sky & Slate InfraGuard Design Language. Maintain unified spacing, Material Symbols icon usage, and component tokens.

10. **Enterprise Simplicity**
    - High-density information without visual clutter. Prioritize 5-second operational clarity over over-engineered complexity.
